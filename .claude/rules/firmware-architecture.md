# 韌體架構規範 (Firmware Architecture)

本專案無線遙控器採用模組化、低耦合之分層架構設計，確保兼顧即時性、可維護性與硬體移植彈性。

## 1. 分層架構設計

```
+-------------------------------------------------------+
| Application Layer (狀態機、按鍵邏輯、OLED UI 畫面)    |
+-------------------------------------------------------+
| Safety & Interlock Layer (急停優先權、對向互鎖保護)    |
+-------------------------------------------------------+
| Protocol Layer (封包封裝、封包計數、CRC16/32 校驗)     |
+-------------------------------------------------------+
| HAL / Driver Layer (GPIO 按鍵防彈跳、I2C OLED、ESP-NOW)|
+-------------------------------------------------------+
```

## 2. 目錄職責劃分

- `include/config.h`：硬體腳位定義（GPIO Pinouts）、計時參數（防彈跳、心跳週期）。
- `include/protocol.h`：通訊封包資料結構體、封包類型列舉、按鍵遮罩定義（傳送端與接收端共用規範）。
- `src/main.cpp`：主程式進入點、系統初始化、主迴圈與狀態機排程。
- `simulator/`：提供獨立於實體板的虛擬機測試介面（Web HMI 面板），方便演算法與視覺反饋除錯。

## 3. 開發鐵律

1. **避免阻塞延遲**：嚴禁在主迴圈中使用 `delay()` 阻塞系統，一律採用非阻塞計時（如 `millis()` 計時器）維護心跳與按鍵掃描。
2. **通訊封包單一規格**：封包結構體一律定義於 `include/protocol.h`，並宣告為封裝對齊（`#pragma pack(push, 1)`），確保不同架構間位元組順序無歧義。
3. **低功耗與休眠考量**：遙控器長時間無任何動作（預設 5 分鐘）應具備逾時自動休眠機制，按壓任意按鈕可由中斷喚醒。
